# Art2UGUI Photoshop 导出

运行 `PS2UGUI_Export.jsx`，将整个 PSD 或选中组导出为 JSON + PNG，完成后自动打开文件夹。PSD 需要保存过；已有未保存编辑可以直接导出。

## 一个 PSD 包含多个面板

导出窗口保留 **导出整个 PSD**，另提供 **导出选中组**：

1. 在 PS 图层面板点选一个顶层普通组本身，例如 `胜利`。
2. 运行菜单脚本，确认窗口显示的当前组名，点击“导出选中组”。
3. 在 PSD 所在目录直接生成 `胜利/胜利_ui_data.json` 及该面板的 PNG。Unity Art Importer 选择这个 `胜利` 文件夹。

组名直接作为面板名，无需加前缀或后缀；同一 PSD 内需要唯一，且不能包含 Windows 文件名非法字符或以 `#` 开头。图层、嵌套组和独立画板不能使用此按钮。每次导出一个活动组。

选中的顶层组仅作为容器，不生成自己的 PNG。保留 PSD 原画布尺寸和原坐标；隐藏的面板组也能直接导出，不改变源文档显隐，组内隐藏及 `#` 规则仍然生效。组外背景、HUD 等不包含在内，需要导出的内容应放入面板组。

组内图片仍需 `img_`、`btn_` 等前缀；普通装饰应放进带前缀的切图组。只有文字而没有可识别图片时，会明确提示整理图片命名。选择单面板 PSD 时，仍可直接使用“导出整个 PSD”。

本功能只改变 PS 的导出范围、输出目录和 JSON 文件名，沿用原有 JSON 格式与图片路径规则，无需修改 Unity Editor 导入代码。例如 `关卡.psd`、`胜利/`、`失败/` 位于同一目录；单面板 PSD 仍用“导出整个 PSD”输出到 `关卡/`。

## 使用规则

- 面板展示前缀 `btn_`、`img_` 和后缀 `%`、`~`、`^N`。其他既有前缀仍可识别。
- 没有全局 1x/2x 选项。`img_logo^0.5` 只将 PNG 宽高减半，Unity 中的可见布局大小不变。
- 倍率标记已从 `*N` 改为 `^N`，不再解析旧 `*N`。旧 PSD/Figma 节点例如 `img_logo*0.5` 需改名为 `img_logo^0.5` 后重新导出，已有 PNG 文件名不变。
- PS 可用 `[宽x高]` 固定图片画布，例如 `img_prop[240x240]`，规则见下文。
- 可选无/1px/2px 透明留边，默认 1px。留边随节点倍率取整，启用时至少有 1 个实际透明像素；JSON 按实际像素比例补偿，可包含小数坐标和尺寸。
- `~` 只作用于当前导出图片：PNG 为白色透明度蒙版，`fontColor` 保存用于 Unity 恢复的原色。普通彩色图片不输出图片 Tint。
- 前缀组输出自身 PNG，内部文字及所有前缀图片（包括 `~` 图片）独立导出，并从父 PNG 中分离。无前缀装饰保留在父 PNG 中。
- 隐藏和 `#` 开头子树不生成独立数据/资源。`#` 子树的可见内容仍可能参与父 PNG。
- 文字输出内容、字号、颜色、对齐等数据，不生成 PNG。普通组递归遍历。
- 输出 `{PSD名}_ui_data.json` 和 PNG；PNG 文件名移除 `^N` 和尾部 `$ % @ ~`，JSON 保留图层原名。

## 固定道具画布（PS）

将节点命名为 `img_prop[240x240]`，输出 `img_prop.png`。默认 PNG 和 Unity 图片矩形均为 240×240、Scale=1：

- 小图保留原大小，居中补透明；大图等比缩小到能完整放入画布，不裁掉图案，不强行拉伸。
- 面板的透明留边包含在指定画布内。例如 480×240 图案、1px 留边会缩为 238×119，再居中放入 240×240；100×50 小图保持 100×50。画布与内容相差奇数像素时，两边留空可相差 1px。
- JSON 图片矩形按指定宽高输出，保持原设计中心。大图缩小时图案的显示大小也随之减小；文字和独立导出的子图片不继承这项尺寸设置。
- 支持非正方形，例如 `img_prop[320x240]`。宽高为正整数，不能重复指定，指定画布必须能容纳所选留边；不作用于文字图层。
- 普通标签如 `img_prop[rare]` 保留原文件名，不视为尺寸；也可写成 `img_prop[rare][240x240]`。
- 可组合 Tint/九宫格：`img_prop~[240x240]` 或 `img_prop[240x240]~`。若还要缩图，`^N` 放最后：`img_prop[240x240]^0.5` 的 PNG 为 120×120，JSON 布局仍为 240×240。

固定画布是本次 PS 扩展，JSON 会带 `fixedCanvas: true`。导入器据此移除文件名中的尺寸后缀，直接使用 JSON 矩形，不再缩放一次。Figma 的普通方括号名称在没有此标记时仍作为原名称解析。使用本功能需要更新后的本地维护导入包，原 0.2.2 Git 发布包不含本次新增解析。

## 与 Unity 的导出协议 v2

JSON 根包含 `schemaVersion: 2`。PS 与 Figma 共同遵循：

| 字段/资源 | 含义 |
| --- | --- |
| 图片 x/y/width/height | PNG 对应的渲染矩形，包含留边；保留小数精度 |
| 图片 rotationZ、scaleX/Y | 旋转和缩放已烘焙进 PNG，分别为 0、1/1；不再恢复智能对象的原始变换 |
| opacity | 当前节点及祖先的有效透明度；PNG 导出副本将当前节点透明度归一为 100%，Unity 应用 JSON 一次。填充、蒙版、效果中的局部透明度保留在 PNG 中 |
| 图片 fontColor | 仅成功置白的 `~` 图片输出；普通图片在 Unity 中使用白色 Image.color |
| ^N | 仅为 PNG 分辨率，不能作为 Unity Transform 缩放，也不能用 PNG 原生尺寸覆盖 JSON 矩形 |
| fixedCanvas | PS 固定画布扩展标记；为 true 时解析 `[宽x高]`，布局仍由 x/y/width/height 决定 |
| 文字 | 字号包含 PS 文字变换及文档分辨率；点文字 `wordWrap=false`，段落文字 `wordWrap=true`，由 Unity 按文字字段还原 |

例：200×200 图案，`^0.5` + 1px 留边得到 102×102 PNG，JSON 含边矩形为 204×204，可见图案仍为 200×200。奇数尺寸缩图时，JSON 留边可能是小数。

Unity 维护源码的 `com.july.ui.authoring` 已同步该协议：使用浮点几何、统一命名解析、保持布局和透明度精度、自动导入 Single Sprite，并返回真实 Prefab 路径、失败及取消结果。导入前检查缺图和输出目录，取消覆盖时不复制资源；覆盖保存保留旧 Prefab GUID。

使用新导出器时也需要更新 Unity authoring 包。未使用旧倍率后缀的历史 JSON 可继续读取基本布局；含 `*N` 的旧节点必须先改名重导。旧旋转、Tint 和透明度数据无法完整恢复新契约，建议重新导出。v2 中历史 `$` 后缀仍可解析，但不会覆盖 JSON 布局尺寸。包的维护源码修改不等于已发布新 UPM 版本。


宿主契约测试覆盖遍历、父子分离、Tint、透明度、缩图、留边、路径和错误清理，并执行 Figma 实际导出逻辑比较两端 JSON。`tests/photoshop-export.test.jsx` 在真实 Photoshop 中新建专用 PSD，检查实际 PNG、JSON、原文档历史及活动图层；产物在 `.tmp/photoshop-export-test/`。

`tests/photoshop-panels.test.jsx` 在真实 PS 中创建两个包含同名路径的面板，验证隐藏组独立导出、原画布/坐标、源显隐/历史/选择及临时文档清理；若 `.tmp/MultiPanelInspection.psd` 存在，还验证业务 PSD 的四个面板，副本与结果均写入 `.tmp/photoshop-panels-test/`。

2026-11-13 已在 Photoshop 24.3.0 实测：调整层不再把组撑成整画布；原尺寸、`^0.5`、`^2`、0/1/2px 留边均正确；50% 图层 PNG 内容 Alpha=255、JSON opacity=50；Tint PNG 内容为白色且边缘全透明；旋转智能对象输出渲染矩形、rotationZ=0，含小数留边且原文档历史不变。真实 PS Tint 和旋转产物也进入 Unity 导入回归。倍率符号迁移后 PS 33 项、Figma 15 项（含真实浏览器）、Unity 31 项均通过，包含旧星号拒绝检查；TypeScript 检查和构建通过。

固定画布新增 6 项原生 PS 用例，验证小图不放大、大图等比缩小、奇数内容居中、0/1/2px 内部留边、非正方形、`^0.5`，并检查 JSON 位置及源文档历史不变。Unity 回归实际导入原生 240×240 PNG，确认资源路径、矩形和 Scale=1；另覆盖 Tint 组合与没有 fixedCanvas 标记时保留方括号原名。

同日根据业务 PSD 的裁边反馈修复：不能直接裁切、缩放仍带矢量蒙版和实时效果的临时图层组，否则 PS 可能重新计算效果，导致边缘变形或透明留边被填满。现在分离子组件后，先合成为透明像素，再裁切、缩图和留边。业务 `img_Copy^0.5` 仍为 102×102 PNG、204×204 JSON 矩形；修复结果与完整渲染参考逐像素一致，四周边缘全部透明，原 PSD 及 JSON 布局保持不变。

文字反馈也已复现并修复：“购物喽”的基准字号为 50.08007，文字矩阵 Y 轴倍率约 2.096642，实际字号为 105；导出时将倍率折算进 fontSize，保持 scaleY=1。点文字不自动换行，避免 TMP 在 310px 字形边界内把总前进宽度 315px 的三个字折成两行。原生 PS 的 72/144dpi、210% 文字变换分别输出 105/210px；使用游戏实际字魂字体、Canvas 和 TMP 网格验证字号 105、三个字符、单行显示。未改变字体映射规则；文字旋转、斜切、非等比变形及 PS/TMP 字形边界差异仍需单独验收。

修复后再次检查了完整链路，补修父子 Tint 重复显示、布局小数截断、滑动条 Fill 丢失 Tint/透明度、低透明度被取整、历史 `$` 覆盖缩图布局，以及文字名称中的 `*` 被错误当作图片倍率解析的问题。

## 限制

- PS 普通图层、组和文字使用可见像素边界，与 Figma 的布局框不同；富文本、文字旋转/缩放、字体及复杂文本效果需单独验收。
- 图片旋转、镜像和透视保留在 PNG 中，Unity 节点不会保留可编辑的原始图片变换。
- `~` 会将整张图片及已合成效果置白，用于单色 Tint；多色图片应不加 `~`。没有可读纯色色源时保留原图并提示。
- 图层组外的剪贴蒙版、背景混合和调整层不会随独立 PNG 复制，需要放入同一导出组。
- 重复导出覆盖同名文件，不清理旧文件；同名 PNG 会提示并由后者覆盖。部分 PNG 失败会明确报告，临时文档始终清理。
